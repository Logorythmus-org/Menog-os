# Menog OS glossary

Use these terms when reading the architecture or proposing a contribution. They describe the
public implementation and its boundaries; they are not a production-readiness or security guarantee.

**reachability ≠ identity ≠ admission ≠ authority ≠ execution**

A reachable endpoint does not identify a peer. A verified identity does not admit it. Peer admission
permits communication trust, not execution authority. An authorized request still has to pass the
runtime's validation and isolation gates before a tool runs.

| Term | Meaning in Menog OS | Start reading |
|---|---|---|
| **Intent** | The desired outcome at the human-input end of the architecture. The core `Goal` represents a planning request with a description, requested verb sequence, budget, and optional workspace/context. Intent is input to planning, not executable permission. | [Core contracts](../packages/core/src/types.ts) |
| **Verb** | A declarative action contract identified by a verb ID. `VerbContract` describes required capabilities, side-effect class, schema versions, and replay/reversal properties. Declaring a verb does not authorize or execute it. | [Verb contracts](../packages/verbs/src/types.ts) |
| **Proposal / plan** | A suggested course of action. `PlannerProposal` reports a disposition and may contain a `Plan` with ordered steps, capability requirements, budget, and approval requirements. The planner can reject a request; an accepted proposal still needs local policy and execution checks. | [Planner](../packages/planner/src/deterministicPlanner.ts) |
| **Policy decision** | The local policy engine's `allow` or `deny` result for a scoped request, with reasons, matched rules, risk, and whether human approval is required. `PolicyResult` also records per-capability outcomes. A requirement for approval is not evidence that approval happened. Core event records separately allow `not_applicable`. | [Policy types](../packages/policy/src/types.ts), [engine](../packages/policy/src/engine.ts) |
| **Capability** | A named action scope, such as `workspace:read` or `git:commit`, associated with side effects, risk, and approval requirements. A requested, declared, or advertised capability is not a grant. The governed tool path checks capability intersection and policy before execution. | [Capability vocabulary](../packages/policy/src/capabilities.ts), [tool gate](../packages/runtime-linux/src/toolruntime/evaluate.ts) |
| **Authority** | Local permission to proceed with a particular action under policy and the applicable runtime boundaries. The README's rule is “Policy is authority”: model output, remote messages, evidence, and rendered state cannot supply it. A policy allowance does not bypass execution validation or isolation. | [Architecture](../README.md#architecture), [execution gate](../packages/runtime-linux/src/gate.ts) |
| **Execution** | The runtime actually attempting an action through its governed execution path. For tools, request validation, registry/manifest checks, capability and policy gates, and isolation checks precede launcher transport. Denied or unsupported isolation outcomes must not be described as a completed run. | [Tool execution](../packages/runtime-linux/src/toolruntime/execute.ts) |
| **Event / evidence** | An inspectable record of input, decisions, or results, rather than permission to act. `MenogEvent` carries actor, time, optional action summaries, and hash-chain fields; `AppendOnlyLedger` validates and appends records and can verify their chain. Evidence can record refusal as well as success. | [Event contract](../packages/core/src/types.ts), [ledger](../packages/event-ledger/src/ledger.ts) |
| **Identity** | The identity claimed and verified for a federation peer. A `NodeId` is derived from its public-key fingerprint; `RuntimeInstanceId` identifies an installation and a runtime epoch identifies an incarnation. Identity/signature verification establishes provenance of data, not execution permission. | [Federation identity](../packages/durable-state/src/federationIdentity.ts) |
| **Peer admission** | An evidenced local decision about a peer's communication trust state. The durable peer registry distinguishes candidate, admitted, quarantined, and retired peers; first contact is not admission. Admission does not grant execution authority. | [Peer registry](../packages/durable-state/src/federationPeers.ts) |
| **Reachability** | The transport fact that bytes could be sent to an endpoint. It does not prove identity, admission, or application acceptance. The transport trust model distinguishes connection state from peer trust state and limits endpoints to local scope. | [Transport trust](../packages/durable-state/src/federationTransportTrust.ts) |
| **Federation** | Exchange of bounded, authenticated messages between peers for local evaluation. The federation bus checks admission, identity/signature, protocol, replay/freshness, and records receipt evidence before exposing payloads as untrusted inbox data. Federation does not combine peers' capabilities or delegate local policy. The public README limits transport to local networking. | [Federation bus](../packages/durable-state/src/federationBus.ts), [public limits](../README.md#what-works-today) |
| **Mesh route** | A planned path over explicit topology observations, describing how bytes would travel. Route planning is bounded and deterministic; a successful route carries `admission: "none"`, `authorization: "none"`, and `executionAuthorized: false`. A route is neither peer admission nor permission to execute. | [Route planning](../packages/durable-state/src/meshRoutePlanning.ts) |
| **GETIG projection** | A read-only mapping of an observability snapshot into a visible GETIG frame. The entity projection maps nodes, relations, routes, refusals, and conflicts while preserving provenance and unknown/stale states. It creates no authority; the current entity projection leaves event and proposal-flow collections empty. A visible frame is not a production renderer. | [Entity projection](../packages/durable-state/src/getigEntityProjection.ts), [frame contract](../packages/durable-state/src/getigRepresentation.ts) |

For broader limits, see [Boundaries and non-goals](BOUNDARIES_AND_NONGOALS_v0.md).
